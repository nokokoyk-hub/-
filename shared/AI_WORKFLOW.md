# AI共有基盤の役割分担

> Notion・GitHub・Obsidian・各種AIチャットをまたいでも、担当AIが現在地を取り違えず、続きから安全に作業するための共通ルール。

## 役割

| 場所 | 正本として持つ内容 |
|---|---|
| **Notion（全体司令塔）** | 全プロジェクトの現進捗の要約、優先順位、担当AI（Codex／Claude Code／各種チャット）、次の受け渡し先 |
| **GitHub／各Gitリポ（現場正本）** | 実コードと差分、正確な作業進捗、アプリ構成一覧、北極星、`docs/current_state.md`、`docs/ai_handoff.md`、テスト結果 |
| **Obsidian（AI共通の外部脳）** | プロジェクト横断ルール、判断理由、失敗・成功、環境・ツール知識。担当AIが変わっても判断を再現するための記憶 |
| **各種チャット（一時作業場）** | 相談・壁打ち・検討中の内容。確定事項は種類に応じた正本へ戻す |

## 作業開始時の突合せ

1. Notionを利用できる場合、全体の現進捗・優先順位・担当AI・次の受け渡し先を確認する。
2. Obsidianの `AI開発脳/index.md` から、必要な横断ルール・失敗ログ・環境設定を読む。
3. 対象GitHubリポの北極星、`docs/current_state.md`、`docs/ai_handoff.md`、構成一覧を読む。
4. 実コード、Git履歴・状態、テスト結果を確認する。
5. 3つの記録と現物を突き合わせ、食い違いを整理してから作業を始める。

NotionまたはObsidianへ接続できないAIは、その旨を報告し、利用できる正本から作業を続ける。読めていない情報を推測で補わない。

## 食い違いの裁定

- 日付が新しいだけで正しいと決めない。情報の種類ごとの正本を優先する。
- 担当AI・全体優先順位はNotionを優先する。
- 実装済み機能・構成・差分はGitHubの実コードとテスト結果を優先する。
- 横断ルール・判断理由・環境知識はObsidianを優先する。
- 北極星と実装が食い違う場合、実装を勝手に正当化しない。目的・仕様の変更が確定しているか確認する。
- GitHub文書が実コードより古いと確認できたら、検証後に文書を更新し、ブランチへコミット・プッシュする。
- 判断不能な衝突は勝手に上書きせず、相違点と根拠を整理してのんへ確認する。

## 作業終了時の戻し先

1. **GitHub**：北極星、正確な現在地、構成一覧、引き継ぎ、検証結果、必要なchangelog・versionを更新する。
2. **GitHub**：確認済みの変更だけをコミット・プッシュする。原則としてブランチとPRを使う。
3. **Notion**：全体進捗の要約、担当AI、次の受け渡し先を更新する。
4. **Obsidian**：他プロジェクトでも役立つ判断・失敗・成功・環境知識と、作業先への短い参照を記録する。

## 二重管理を防ぐ基準

- 全体の担当と要約 → Notion
- その現場の事実 → GitHub
- 他プロジェクトでも役立つ記憶 → Obsidian
- 未確定の相談 → チャット

同じ詳細を複数箇所へ丸ごと複製せず、概要とリンクでつなぐ。

## 安全

- パスワード、APIキー、トークンの中身は、Notion・GitHub・Obsidianのどこにも記録しない。
- 公開リポには個人情報、秘密、内部URLを入れない。
- 認証・決済・DBスキーマ・本番導線は、明示的な依頼と確認なしに変更しない。
