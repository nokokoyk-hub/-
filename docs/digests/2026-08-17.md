# 作業ダイジェスト 2026-08-17（JST）

## 事象

Codexが頼んでいない作業を何時間も続け、使用量を限界まで消費。本命のビルドができなくなった（のん報告）。

## 原因

`codex-kit/global/AGENTS.md` は「やること」（正本巡回・終了時の締め作業7点・改善提案）だけが定義され、
作業範囲の上限・停止条件・リトライ上限がなかった。人間の確認ゲートがないCodexクラウドでは、
儀式をすべて毎回こなし、止まる理由がないまま走り続ける。

## 対応

1. `codex-kit/global/AGENTS.md` に「作業範囲と止まりどころ（最優先）」セクションを新設
   - 依頼されたことだけ実行。依頼外は「次の提案」として報告のみ
   - 完了したら止まる。正本確認は依頼に必要な範囲だけ。接続不可の正本は再試行しない
   - 同じ失敗への対処は2回まで。長い処理の無確認再実行禁止
   - 長引くと分かった時点で停止して進捗報告
2. 「作業の終わり」の締め作業一式を、明示的に頼まれたときだけに変更
3. 開始時の正本確認を「依頼に必要な範囲だけ」に限定
4. `codex-kit/README.md` に「暴走したときの止め方」を追加（即時停止はCodex側のStopのみ）

## 反映条件

mainマージ → Maintenance / Setup script 実行 → **新しいチャット**で実測確認。
既に走っている古いタスクには効かないため、暴走中のタスクはCodex側でStopするのが先。
